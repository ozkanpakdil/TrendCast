## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0f172a` (slate-900) / `#f8fafc` (light.bg) | Page background (dark default / light theme) |
| Secondary (30%) | `#1e293b` (slate-800) / `#ffffff` (light.surface) | Cards, badge containers, panel surfaces |
| Accent (10%) | `#3377ff` (brand-500) | Active/focused interactive elements, primary CTA, focus ring only |
| Destructive | `#dc2626` (bear) | Degraded/error health state only |

**Semantic health states** (the phase's core visual contract — maps to `SourceHealthEntry`):

| State | Color | Token | Meaning |
|-------|-------|-------|---------|
| Healthy | `#16a34a` (bull) | `text-bull` / `bg-bull/15` | Source fetched items at last cycle, no failures |
| Stale | `#f59e0b` (amber) | `text-amber-500` / `bg-amber-500/15` | `lastFetchedAt` older than staleness threshold (hourly cycle missed) |
| Degraded | `#dc2626` (bear) | `text-bear` / `bg-bear/15` | `consecutiveFailures > 0` or last fetch returned 0 items |
| No-data | `#6b7280` (neutral) | `text-neutral` / `bg-neutral/15` | No `SourceHealthEntry` yet (never fetched) or fetched 0 with no failure |

**Accent reserved for:** active/focused interactive controls, the primary "Run Correlation" button, and focus rings. **Never** used for health status badges — health uses the semantic `bull`/`amber`/`bear`/`neutral` set above. **Destructive** (`bear`) is reserved for the degraded health state only; there are no destructive user actions in this phase.

**Focal point:** The primary **Run Correlation** button is the visual anchor of the screen — it is the only element that draws the eye first and the only accent-filled control. The `SourceHealthIndicator` is a **secondary read-only row** that must not compete: it renders in muted semantic badge colors (never accent), sits below the primary action, and reads as supporting telemetry rather than an interactive control.

**Source:** `tailwind.config.ts` brand/semantic palette + existing `slate-*`/`light-*` surface convention in `src/dashboard/`. The `SourceHealthIndicator` must render identically in dark (default) and light themes via the existing `isDark` prop pattern used by `CorrelationStatsBar`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **Run Correlation** (existing trigger; unchanged — this phase adds no new primary action) |
| Health indicator — healthy | `{Source} · Healthy` |
| Health indicator — stale | `{Source} · Stale` |
| Health indicator — degraded | `{Source} · Degraded` |
| Health indicator — no data | `{Source} · No data` |
| Fetched/correlated detail | `fetched {N} · correlated {M}` |
| Empty state heading | `No health data available` |
| Empty state body | `Run a collection to see per-source status.` |
| Error state | `Health data unavailable — check your connection and run collection again.` |
| Destructive confirmation | none (no destructive actions in this phase) |

**Source:** RESEARCH.md Pattern 2 ("fetched N · correlated M") + existing `NewsFeed.tsx` empty-state convention ("No news collected yet. Wait for the next hourly collection."). The health indicator's primary job is to make the REL-01 root cause visible: a source showing `fetched 10 · correlated 0` is distinguishable from one showing `No data`.
