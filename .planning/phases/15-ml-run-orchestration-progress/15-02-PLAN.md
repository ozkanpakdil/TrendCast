# Phase 15 Plan 02: Model-Download Progress Events (loading-model phase)

**Requirement:** MLPROG-02 — first-run model download surfaces per-file `initiate`/`download`/`progress`/`done` events through the existing `CORRELATION_PROGRESS` channel as a `loading-model` phase, instead of silence.

## Tasks

### Task 1 — `createPipelineWithFallback` progress_callback (`src/services/engine/ml/transformers.ts`)

- Add optional `onModelDownload?: (info: { status: string; file?: string; progress?: number; loaded?: number; total?: number }) => void` parameter.
- Pass `progress_callback: onModelDownload` into `lib.pipeline(task, model, options)` (both WebGPU attempt and WASM retry).
- Thread the callback through all five `get*Pipeline()` functions (embedding/sentiment/ner/llm) as an optional trailing param; cache key unchanged (pipeline identity, not download state).

### Task 2 — Plumb to the worker (`src/services/engine/ml.ts` + `src/workers/ml-worker.ts`)

- `get*Pipeline` call sites in `ml.ts` accept and forward the callback.
- Worker: build a `loading-model` progress emitter from the callback — map transformers.js statuses: `initiate` → phase `loading-model` current 0/1; `progress` → `current = loaded ?? progress`, `total = total ?? 100`; `done` → advance. Emit through the existing `postMessageToHost({ type: 'progress', … })` channel (no protocol change).
- Cancel check inside the callback (throws like `onProgress` does).

### Task 3 — UI label (`src/dashboard/App.tsx`)

- `phaseLabel` already maps `'loading-model'` → 'Loading model…' — verify; extend the progress card to show the file name when phase is `loading-model` (e.g. `Loading model… onnx/model_q8.onnx`).

### Task 4 — Tests

- `tests/unit/model-download-progress.test.ts`: fake transformers lib emits `initiate`/`progress`/`done`; assert `loading-model` progress messages carry file/loaded/total; assert callback forwarded on WASM retry path; assert cancel inside callback aborts.
