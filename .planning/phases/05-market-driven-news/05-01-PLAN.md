<objective>
Establish the single-source category taxonomy and persist a category on every `NewsItem` at collection time, so the market-driven news view and future export read a consistent, drift-free category.

Purpose: MKT-02 requires a consistent category taxonomy reused across markets and news. D-01..D-04 lock the taxonomy to a single `src/config/taxonomy.ts` module with 3 categories (finance/politics/technology) and deterministic precedence (politics > finance > tech). D-02 requires the category be assigned at collection time and persisted on `NewsItem`. D-13/D-16 require the new storage key + config constants so the derived snapshot is bounded and budget-accounted.

Output: `src/config/taxonomy.ts` (taxonomy + `classifyCategory`), `category` on `NewsItem`, category assignment in `collectNews`, `CONFIG.storage.marketNewsView` + `CONFIG.marketNews.{minVolume,capPerCategory}`, `trendcast:market-news-view` in `BUDGET_KEYS`, and `tests/unit/taxonomy.test.ts`.
</objective>

  <name>Task 1: Create single-source taxonomy module + unit tests</name>
  <files>src/config/taxonomy.ts, tests/unit/taxonomy.test.ts</files>
  <behavior>
    - Test 1: `classifyCategory('Fed raises rates to fight inflation')` returns `'finance'` (finance keyword wins when no politics keyword present)
    - Test 2: `classifyCategory('Senate passes tariff bill on tech imports')` returns `'politics'` (politics precedence beats finance 'tariff' and tech 'tech' — D-04)
    - Test 3: `classifyCategory('AI chip startup raises funding')` returns `'technology'`
    - Test 4: `classifyCategory('unrelated headline about weather')` returns `'finance'` (default fallback)
    - Test 5: mutual exclusivity — a headline containing keywords from multiple categories maps to exactly one category (the highest-precedence match)
    - Test 6: `CATEGORY_ORDER` equals `['politics', 'finance', 'technology']` and `CATEGORY_RULES` has exactly those 3 keys (D-03)
  </behavior>
  <action>
    Create `src/config/taxonomy.ts` as the single source of truth for the category taxonomy (D-01). Export:
    - `export type NewsCategory = 'finance' | 'politics' | 'technology'` (D-03, reusing the `redditCategories` labels).
    - `export interface CategoryRule { id: NewsCategory; label: string; keywords: string[] }` — `label` reuses the `redditCategories` label text (e.g. `'💰 Finance & Stock Market'`, `'🏛️ Politics'`, `'💻 Technology'`).
    - `export const CATEGORY_ORDER: NewsCategory[] = ['politics', 'finance', 'technology']` — the single place encoding precedence politics > finance > tech (D-04). First match wins.
    - `export const CATEGORY_RULES: Record<NewsCategory, CategoryRule>` — keyword/entity rules per category. Use the research Pattern 1 keyword sets as a starting baseline (politics: election/senate/congress/president/geopolitics/war/tariff; finance: stock/fed/rate/earnings/inflation/bitcoin/market; technology: ai/chip/semiconductor/software/startup/tech). You have discretion to refine keyword lists, but keep them deterministic and lowercase.
    - `export const TAXONOMY_VERSION = 1` — version constant so future rule changes can trigger re-classification (Pitfall 3).
    - `export function classifyCategory(headline: string): NewsCategory` — lowercases the headline, iterates `CATEGORY_ORDER`, returns the first category whose `keywords.some((kw) => text.includes(kw))`; falls back to `'finance'` (the app's focus) when nothing matches.
    Do NOT hardcode any keyword list outside this module — the classifier, the aggregation module (05-02), and the dashboard (05-03) must all import from here (Pitfall 3 anti-pattern).
    Create `tests/unit/taxonomy.test.ts` covering the behaviors above. Use `bun run test -- tests/unit/taxonomy.test.ts` as the automated gate.
  </action>

    <automated>bun run test -- tests/unit/taxonomy.test.ts</automated>
  </verify>

  </done>
