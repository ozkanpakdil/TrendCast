<objective>
Close gap G-09-1: a healthy-but-quiet news source (304 Not Modified, no new headlines) is mislabeled 'Degraded · fetched 0' instead of 'Healthy' even though its stored news is present and correlated.

Purpose: `collectNews()` records `itemCount: 0` when a source returns 304 (unchanged) — correctly NOT incrementing `consecutiveFailures` — but `computeHealth()` labels any entry with `itemCount === 0` as `'degraded'`. So a healthy-but-quiet source (304, itemCount 0, consecutiveFailures 0) is mislabeled. The fix distinguishes "unchanged (304)" from "empty/failed fetch" so a 304-unchanged source with stored news is healthy, while a genuinely failed or empty fetch stays degraded.

Output: `SourceHealthEntry` gains an optional `lastUnchanged` flag recorded by `collectNews` on a 304; `computeHealth` treats an unchanged source as healthy when `consecutiveFailures === 0`; unit tests prove the new behavior and preserve the existing degraded cases.
</objective>
