<objective>
Deep-merge `enabledSources` in every settings load path so newer source flags (`seekingalpha`, `investing`, `googleFinance`) default to `true` for existing users while preserving explicit user preferences.

Purpose: Fixes NEWS-01 — the root cause of missing Seeking Alpha / Investing.com headlines is the shallow merge `{ ...DEFAULT_SETTINGS, ...stored }` in three load sites, which replaces the whole nested `enabledSources` object with the stored partial (missing the newer keys). A deep-merge backfills missing flags from defaults without overwriting present keys.

Output: A pure, unit-testable `deepMergeSettings()` helper in `src/utils/settings.ts`, wired into all three load sites (background `getSettings`, dashboard `App.tsx`, popup `useSettings.ts`), plus its unit test.
</objective>

  <action>
    Create `src/utils/settings.ts` exporting a pure function `deepMergeSettings(defaults: ExtensionSettings, stored: Partial<ExtensionSettings> | undefined): ExtensionSettings`. Behavior: when `stored` is `undefined`, return `defaults` unchanged. Otherwise shallow-merge top-level fields as `{ ...defaults, ...stored }` and deep-merge `enabledSources` as `{ ...defaults.enabledSources, ...(stored.enabledSources ?? {}) }`. Guard the deep-merge: only spread `stored.enabledSources` when it is a plain object (`typeof === 'object' && !Array.isArray`); otherwise fall back to `defaults.enabledSources` so malformed/corrupted stored data cannot inject junk keys. This makes newer source flags (`seekingalpha`, `investing`, `googleFinance`) default to `true` while present keys (explicit user preferences) win. Import `ExtensionSettings` as a type and `DEFAULT_SETTINGS` as a value from `@/types`. Do NOT import `browser` or `CONFIG` in this module — keep it pure and storage-free so it is trivially unit-testable.

    In `src/background/index.ts`, replace the body of `getSettings()` (currently `return { ...DEFAULT_SETTINGS, ...stored };`) with `return deepMergeSettings(DEFAULT_SETTINGS, stored);` and add `import { deepMergeSettings } from '@/utils/settings';` to the import block. This is the collection path: `runCollection()` reads `settings.enabledSources` and only pushes `seekingalpha`/`investing` into `newsSources` when those flags are truthy, so deep-merging here is what makes the headlines actually get collected.

    Create `tests/unit/settings-deep-merge.test.ts` (Vitest, globals enabled, no browser mock needed since the helper is pure). Cover at minimum: (1) `undefined` stored returns `defaults` unchanged; (2) a stored `enabledSources` missing `seekingalpha`/`investing`/`googleFinance` yields those three flags `true`; (3) an explicit `seekingalpha: false` in stored is preserved (not overwritten by the default `true`); (4) a top-level stored field (e.g. `collectionIntervalMinutes`) overrides the default; (5) a non-object `enabledSources` (e.g. a string) falls back to `defaults.enabledSources` without throwing.
  </action>
