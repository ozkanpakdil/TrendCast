## UI Considerations

> State coverage for the news tab and settings toggles. This phase must NOT regress any existing state. The deep-merge + migration only changes WHICH sources are collected/rendered — it must not alter how any state renders.

Applicable state considerations resolved: 5 covered, 0 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | news list-collection | ✅ covered | Empty results render the documented "No news collected yet. Wait for the next hourly collection." copy (`NewsFeed.tsx`). Deep-merge does not touch this branch. |
| populated | news list-collection | ✅ covered | Populated grid renders all 6 sources via `VirtualizedGrid` with per-source tile colors. After deep-merge, `seekingalpha`/`investing`/`googleFinance` flags default `true`, so their tiles appear for existing users. |
| partial | news list-collection | ✅ covered | A source with no items simply contributes no tiles; the grid renders whatever `news` array contains. Deep-merge does not change this. |
| long-text | news tile (static-content) | ✅ covered | Headline clamped to 2 lines (`WebkitLineClamp: 2`); summary `line-clamp-1`; source label + timestamp at 9px. Unchanged. |
| overflow | news list-collection | ✅ covered | `VirtualizedGrid` virtualizes the list; tiles have `minHeight: 100px`. Unchanged. |
| zero-one-many | news list-collection | ✅ covered | Zero → empty state; one/many → grid. Singular/plural handled by the grid layout, not copy. Unchanged. |
| loading | news list-collection | ✅ covered | Loading handled upstream by the dashboard hook (`useMarketNews`); `NewsFeed` receives a settled array. Unchanged. |
| error | news list-collection | ✅ covered | Error handled upstream by the dashboard hook; `NewsFeed` receives a settled array. Unchanged. |

**Settings-toggle state (migration impact):** The popup `Settings.tsx` toggle list already includes `seekingalpha` and `investing` rows. After migration backfills missing flags to `true`, these toggles render **checked** for existing users (previously they would render `undefined` → unchecked). This is the intended fix and must be verified: a user who never touched these toggles sees them ON; a user who explicitly disabled a source keeps it OFF (deep-merge never overwrites an explicit preference).
