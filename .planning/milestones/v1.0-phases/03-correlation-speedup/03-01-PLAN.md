<objective>
Build the shared `InvertedIndex` — a hand-rolled `Map<keyword, number[]>` that pre-filters candidate contracts for correlation, collapsing the O(n×m) nested loop to O(n×k) candidate filtering. This is the foundation every engine (heuristic + ML) consumes in later plans.

Purpose: The inverted index is the enabler for the whole phase. It must be correct, dependency-free, and provably a superset of the naive-loop matches for keyword-overlap engines, so later equivalence tests hold.
Output: `src/services/engine/index.ts` (the `InvertedIndex` class + incremental cache), `tests/unit/index.test.ts` (unit tests), `tests/unit/fixtures.ts` (shared fixtures reused by all equivalence tests).
</objective>

  <action>
    Create `src/services/engine/index.ts` exporting an `InvertedIndex` class and a `getInvertedIndex` cache helper. Follow the existing index-class shape (`private readonly` Map field + methods) used by `ZeroShotIndex`/`EmbeddingIndex`.

    `InvertedIndex` API:
    - `static build(items: Indexable[], opts?: { includeEntityKeywords?: boolean }): InvertedIndex` — where `Indexable = { keywords: string[]; question?: string; text?: string }`. Iterate items in order; for each item collect its token set: always `item.keywords`, and when `opts.includeEntityKeywords` is true also `extractEntityKeywords(item.question ?? item.text ?? '')`. Deduplicate the token set per item (a `Set`). For each token, push the item's index into the postings list: `map.get(k) ?? map.set(k, []).get(k)!.push(i)`. Preserve contract order so `candidates` returns indices in the same order the naive loop would visit them.
    - `candidates(keywords: string[]): number[]` — union the postings lists for each keyword into a `Set<number>` (dedup), return `[...set]` (insertion order = contract order). Empty keyword array returns `[]`.
    - `has(keyword: string): boolean` and `get size(): number` for introspection/tests.
    - `static readonly TINY_INPUT_THRESHOLD = 2` — the naive-fallback threshold (inputs with fewer items than this skip the index).

    `getInvertedIndex(items, opts)` — module-level incremental cache: compute a deterministic version hash over `items.map(i => i.id).join('\u0000')` (use a small FNV-1a hash function defined in the same file). Keep a module-level `Map<string, InvertedIndex>`; if the hash is cached, return the cached index; else build, cache, return. This satisfies the "cached by data version" requirement (A3 in RESEARCH.md). Note: `Indexable` must carry `id` for the hash — extend the type to `{ id: string; keywords: string[]; question?: string; text?: string }`.

    Do NOT add any runtime dependency. Do NOT re-tokenize contract text with a different function — the index is built from the already-extracted `keywords` arrays (single tokenization source, anti-drift guard Pitfall 1).

    Create `tests/unit/fixtures.ts` exporting named constants reused by all equivalence tests: `mockContract` (a `MarketContract` with `id`, `platform`, `question`, `outcomes`, `endDate`, `keywords`, `lastUpdated`), `mockSignal` (a `SocialSignal` with `id`, `platform`, `text`, `author`, `metrics`, `timestamp`, `keywords`, `sentiment`, `virality`), and a `newsItem(source, headline)` factory that builds a `NewsItem` with `keywords: extractKeywords(headline)` (mirror the `newsItem()` helper in `tests/unit/correlation-threshold.test.ts`). Include a small set of hand-verified golden fixtures (D-02): e.g., a cashtag-only contract/signal pair and a hashtag-only pair with known expected matches.

    Create `tests/unit/index.test.ts` covering: `build()` populates the map (assert `size` and `has`); `candidates()` returns correct contract indices for overlapping keywords; empty keyword array → `[]`; single contract; single signal; duplicate keywords deduped (a contract with `['btc','btc']` indexes once); cashtag/hashtag-only texts; `includeEntityKeywords: true` adds entity-derived postings; `getIncrementalIndex` returns the same instance for an unchanged contract set and a fresh one when the set changes; tiny-input fallback (fewer than `TINY_INPUT_THRESHOLD` items → the caller skips the index, asserted via the threshold constant).
