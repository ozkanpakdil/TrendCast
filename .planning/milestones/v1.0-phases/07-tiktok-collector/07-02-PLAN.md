<objective>
Add a separate `SocialSourceHealth` map and a single TikTok health badge so the user sees a graceful-degradation indicator when TikTok is unavailable (D-02, success criterion 3).

Purpose: SRC-01 requires a "source health indicator" for graceful degradation. The existing `SourceHealth` is keyed by `NewsSource` only; D-02 mandates a separate `SocialSourceHealth` map (`Partial<Record<SocialPlatform, SourceHealthEntry>>`) stored alongside it, so we do NOT touch the `NewsSource`-keyed union. The content script reports health; the dashboard renders one TikTok badge reusing the existing `computeHealth` helper.

Output: `SocialSourceHealth` type + storage, content-script health reporting, a `SocialHealthBadge` dashboard component, and unit tests.
</objective>
