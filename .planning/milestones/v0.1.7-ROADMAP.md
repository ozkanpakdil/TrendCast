# Milestone v0.1.7: Dashboard UX Polish

**Status:** ✅ SHIPPED 2026-08-30
**Phases:** 17-18
**Total Plans:** 2 (executed inline — no formal plan files; work verified via typecheck/lint/445 unit tests/e2e/build + live screenshots)

## Overview

Make the dashboard read as information, not decoration — based on a live screenshot review of every tab: news cards differentiate by source with readable hierarchy, hype cards surface the virality score and engagement, the header shows human-relevant info only, navigation is grouped and consolidated, and density adapts to the user.

## Phases

### Phase 17: Feed Card & Header Polish

**Goal**: The two feed tabs read as information, not decoration — news cards differentiate by source with readable hierarchy, hype cards surface the virality score and engagement, the header shows human-relevant info only, and the popup renders each section exactly once
**Depends on**: Nothing (first phase of milestone)
**Requirements**: UX-01, UX-02, UX-03, UX-04
**Success Criteria** (what must be TRUE):

  1. News tab: cards use a neutral surface with a per-source accent (left border + source label color) instead of full saturated backgrounds; no two adjacent sources look identical; text contrast ≥ WCAG AA on both themes
  2. News cards show article publish time (from `publishedAt`), not the collection batch time, and keyword chips are capped at 3 with a `+N` overflow indicator
  3. Hype Feed: virality score is visually prominent (heat-colored badge + thin score bar), and X/TikTok cards show engagement metrics when available so they carry the same information density as Reddit cards
  4. Dashboard header: build version string moves out of the header (visible in Settings), and last collection renders as relative time ("8m ago") with the absolute time on hover
  5. Popup home tab renders the FAQ section at most once (duplicate blocks removed)

**Status**: Complete — verified visually on live v0.1.7 build (test-results/v017-*.png)

### Phase 18: Navigation & Density

**Goal**: The dashboard navigation is scannable and the feed density adapts to the user — tabs are grouped into labeled sections, sentiment is visible on news cards, and a compact/comfortable toggle controls grid density
**Depends on**: Phase 17 (density toggle builds on the reworked card components)
**Requirements**: UX-05, UX-06, UX-07
**Success Criteria** (what must be TRUE):

  1. Tab navigation groups tabs under small section labels while keeping single-click access to every tab
  2. News cards show a sentiment indicator (colored dot: green/red/neutral) derived from the item's sentiment when available
  3. A density toggle (comfortable/compact) on the Hype Feed and News tabs switches grid card size, persists in settings, and defaults to comfortable
  4. All existing unit + e2e tests pass; new behavior covered by unit tests where testable (density setting persistence, tab grouping render)

**Status**: Complete — scope extended during execution per user request (see Scope Extension below)

## Scope Extension (Phase 18, user-directed)

During execution the user requested **real tab consolidation** beyond grouping. Delivered:

- **11 tabs → 7 tabs**: `feed | markets | news | correlations | alerts | help | settings`
- **Watchlist** merged into the Markets tab (bottom section, "⭐ Your Watchlist")
- **Market News** merged into the News tab (segmented control: "All news" / "🎯 Market-driven")
- **Run History** merged into the Correlations tab ("📊 Run History" section); standalone HistoryChart removed
- **Community + FAQ** merged into a single Help tab (FAQ content + Telegram/GitHub community cards + privacy note)
- **Star-click bug fix** (`MarketOdds.tsx`): star inside an `<a href>` tile called only `stopPropagation()`, so the browser followed the market URL instead of starring. Fixed with `e.preventDefault()` + `e.stopPropagation()` in both heatmap and grid views.
- **e2e suite rewritten** for the 7-tab layout (tab-switch tests, Watchlist-in-Markets, Run-History-in-Correlations, Help = FAQ + Community)

## Milestone Summary

**Key Decisions:**

- Decision: Consolidate tabs rather than just group them (Rationale: user wanted fewer tabs; related content belongs together — watchlist is market-scoped, run history is correlation-scoped, community+FAQ are both "help")
- Decision: `stopPropagation` is not enough inside anchors — must also `preventDefault` (Rationale: React handler suppression does not stop native navigation)
- Decision: Segmented control for News view switching instead of a separate tab (Rationale: keeps one-click access, halves nav count)
- Decision: `feedDensity` setting added to `ExtensionSettings` with deep-merge backfill (Rationale: consistent with settings migration pattern from v0.1.5)

**Issues Resolved:**

- Star click opened the market page instead of adding to watchlist (root-caused + fixed)
- e2e suite asserted 9 tabs while the app had 11 (stale from v1.0 era) — now asserts the real 7-tab layout
- Popup rendered FAQ blocks twice — deduplicated

**Issues Deferred:**

- Live-browser visual confirmation of Help/Markets tab content after click (drive-firefox click-mode screenshot silently fails; e2e Playwright suite covers the rendering instead)

**Technical Debt Incurred:**
