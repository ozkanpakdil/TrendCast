<objective>
Add three stock-indicator RSS feeds (`usaStocksIndicator`, `stockScreener`, `stockScreener2`) as new `NewsSource` values, collected through the existing rss2json.com CORS proxy and tracked for per-source health/staleness.

Purpose: This is the first phase of milestone 0.1.5. It extends the existing, well-tested news pipeline (collector → health → merge → storage) with three verified-live feeds. The only genuinely new logic is deriving the item `id` from the feed `guid` (not `link`) for the two screener feeds, whose items all share a single `link` — using `link` would collapse every item to one via `mergeNews`'s Map dedup.

Output: Three new sources collected, stored under their own keys, health-tracked, and covered by unit tests. No new npm packages.
</objective>

|----------|-------------|
| rss2json proxy → collector | Untrusted feed content (titles, descriptions, guids) crosses into the extension from an external service |
| collector → storage | Normalized `NewsItem` records are persisted to `chrome.storage.local` |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-01 | Tampering | `collectFromSource` item mapper | low | mitigate | Strip HTML tags from descriptions; omit `summary` for the table-heavy screener feeds; `maxNews` cap bounds storage |
| T-11-02 | Tampering | `CONFIG.scrape` URLs | low | accept | Feed URLs are hardcoded in `CONFIG` (not user-supplied); no injection surface |
| T-11-03 | Tampering | `NewsItem.headline`/`summary` rendering | low | mitigate | Headlines/summaries are rendered as text (React escapes); no `dangerouslySetInnerHTML` in the dashboard |
| T-11-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new packages installed this phase; only external dependency is the rss2json.com proxy already in use and covered by `host_permissions` — no package-legitimacy gate applies |
